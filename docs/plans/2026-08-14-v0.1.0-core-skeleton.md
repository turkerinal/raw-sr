# v0.1.0 Core Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-optimized:subagent-driven-development (recommended) or superpowers-optimized:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the minimal end-to-end pipeline that loads multiple RAW frames, calibrates and demosaics them early, filters out blurry frames, aligns frames with global homography, fuses them via weighted shift-and-add, and exports a 16-bit linear TIFF — with a minimal PySide6 UI for file selection and output.

**Architecture:** A PySide6 desktop app where the UI (`ui/`) dispatches processing to a QThread worker that runs the core pipeline (`raw_sr/core/`). The pipeline loads RAW files via `rawpy`, applies sensor calibration (black level subtraction, white balance, white level normalization, dead pixel correction), demosaices immediately, scores each frame for sharpness via Laplacian variance, globally aligns frames using ORB features + RANSAC homography, fuses aligned frames with SNR-weighted shift-and-add, and writes a 16-bit linear TIFF. The UI provides a minimal file selection dialog, process button, progress indicator, and save dialog.

**Tech Stack:** Python 3.14, PySide6 (Qt6) for UI, rawpy + LibRaw for RAW I/O, NumPy + OpenCV for image processing, pytest for tests.

**Assumptions:**
- Assumes a Linux environment with PySide6 and rawpy installed — will NOT work on systems lacking these dependencies.
- Assumes RAW files are standard formats readable by rawpy (CR2, NEF, ARW, DNG) — will NOT work with unknown or proprietary RAW formats not supported by LibRaw.
- Assumes user provides 2+ RAW files with the same static scene — will NOT produce meaningful results with 0 or 1 input file (pipeline requires multiple frames for stacking/SR).
- Assumes sufficient overlap between frames (full scene visible in all frames, per "Mode A" requirement) — does NOT handle frames with significant framing differences (that's V2/Mode B).
